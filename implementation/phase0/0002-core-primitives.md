# 0002 — Core primitives (mce-core)

- **Phase:** 0
- **Workstream:** core-engine
- **Effort:** Small
- **Owner:** unassigned
- **Status:** done

## Objective

Shared primitives used by every crate: structured logging, a common error type, stable-ID
generation, and canonical hashing.

## Background

`SPEC-004 §5.1` (stable MCL IDs — globally unique, immutable, generated by the core, not
trusted from model output). `SPEC-005 §22` (determinism: canonical hashes exclude variable
metadata). `SPEC-001 NFR-002` (transparent errors).

## Dependencies

`phase0/0001`.

## Implementation Notes

- `tracing` for logging; a `MceError` enum with an `Unimplemented` variant carrying the
  owning-component tag (`SPEC-005 §17`).
- `new_id(prefix)` produces sortable IDs (`concept-…`, `tx-000001` style). IDs must never be
  derived solely from display names.
- `canonical_hash(&serde_json::Value)` produces a stable `sha256:…` over key-sorted JSON,
  excluding fields marked as variable metadata (timestamps).

## Acceptance Tests

- Unit test: two hashes of the same logical value (different key order) are equal.
- Unit test: a metadata-only difference (timestamp) does not change the hash.
- Unit test: generated IDs are unique and carry the requested prefix.

## Benchmark Coverage

`COMP-GEN-009` precursor (deterministic hashing).

- MCL element(s): identifier rules `SPEC-004 §5`.
